## 2. 新規発見・特筆事項（当月のtab2作業で判明したこと）

1. **【定義の統一・要承認】有償注文の統一（2026-06・2026-08のM0が8月版から各−1人）。** 原因は`THANKYOU-LypoC10K`（定額値引・純額¥0）の`105-set`注文2件。8月版は初回購入に数え、現行標準は除外。**全章を有償注文（`total_price−current_total_tax>0`）に統一して実行した**。テンプレート（`reference_customer_analysis_queries.md`）10-3・8章・9章は有償注文条件が無く、C+Ceraでそのまま流用するとM0が章間で1人ずれる（5章M0=426/1,013/547/702/396/490/626/166/110に5-3・5-4の人数を一致させるための措置）。CYS0810（＝pitfalls㉓）と同種の「実質無償注文は新規にカウントしない」方針と整合。**西守さんの承認が必要**（8章「未解決」①）。
2. **8月末確定セルは9月末の再計算でも変わらない。** 5章のアイテム新規・純粋新規（確定セル全件）・5-1（30/60/90日F2）・5-4（AVG）は、基準日2026-08-31と2026-09-30で完全一致。月末日基準の確定判定は安定している。

### Q1. 5章・5-2章：M+N継続率（アイテム新規／純粋新規／周期別）— 10-1＋10-2 の統合版

  FROM `spic-core.public.shopify_orders` so, UNNEST(JSON_EXTRACT_ARRAY(so.line_items)) item

  SELECT b.base, v.subscription_id, CAST(v.customer_id AS STRING) AS cid, MIN(v.first_order_dt) AS fo, MIN(v.snapshot_ym) AS first_snap,
    ARRAY_AGG(STRUCT(v.cycle_count AS n, v.cycle_unit AS u) ORDER BY v.snapshot_ym LIMIT 1)[OFFSET(0)] AS c

    CASE WHEN s.cid IS NULL THEN 'spot' WHEN (s.u='月' AND s.n=1) OR (s.u='日' AND s.n=28) THEN '1m' WHEN s.u='月' AND s.n=2 THEN '2m' WHEN s.u='月' AND s.n=3 THEN '3m' ELSE 'other' END AS bucket

### Q4. 5-4章：コホート別LTVマップ（8章のC+Cera版・税抜÷1.08）
```sql
WITH bases AS (SELECT DATE(b) AS base FROM UNNEST(['2026-08-31','2026-09-30']) b),
items AS (
  SELECT so.customer_id, DATE(so.created_at) AS order_date,
    SAFE_CAST(JSON_EXTRACT_SCALAR(item,'$.price') AS FLOAT64) * SAFE_CAST(JSON_EXTRACT_SCALAR(item,'$.quantity') AS FLOAT64) AS line_rev

    AND bm.brand='C+Cera' AND DATE(so.created_at)<='2026-09-30'),
cd AS (SELECT b.base, i.customer_id, i.order_date, ROUND(SUM(i.line_rev)/1.08, 2) AS brand_rev FROM items i JOIN bases b ON i.order_date<=b.base GROUP BY 1,2,3),
anchor AS (SELECT base, customer_id, MIN(order_date) AS bfd FROM cd WHERE brand_rev>0 GROUP BY 1,2),
life AS (SELECT customer_id, MIN(DATE(created_at)) AS life_first FROM `spic-core.public.shopify_orders` WHERE test=0 AND customer_id IS NOT NULL AND cancelled_at IS NULL AND (total_price-current_total_tax)>0 GROUP BY 1),
anchored AS (SELECT a.base, a.customer_id, a.bfd, (l.life_first = a.bfd) AS is_pure FROM anchor a LEFT JOIN life l USING (customer_id)),   -- ★純粋新規はcustomer_masterでなくshopify_ordersから直接算出
w AS (
  SELECT an.base, an.customer_id, an.bfd, an.is_pure,
    SUM(IF(DATE_DIFF(c.order_date, an.bfd, DAY) BETWEEN 0 AND 30, c.brand_rev, 0)) AS l30, SUM(IF(DATE_DIFF(c.order_date, an.bfd, DAY) BETWEEN 0 AND 60, c.brand_rev, 0)) AS l60,

    SUM(IF(DATE_DIFF(c.order_date, an.bfd, DAY) BETWEEN 0 AND 180, c.brand_rev, 0)) AS l180, SUM(IF(DATE_DIFF(c.order_date, an.bfd, DAY) BETWEEN 0 AND 365, c.brand_rev, 0)) AS l365
  FROM anchored an JOIN cd c ON an.base=c.base AND an.customer_id=c.customer_id AND c.order_date>=an.bfd GROUP BY 1,2,3,4)
SELECT FORMAT_DATE('%Y-%m-%d', base) AS base, FORMAT_DATE('%Y-%m', bfd) AS cohort, COUNT(*) AS cust, COUNTIF(is_pure) AS pure_cust,
  ROUND(AVG(l30)) AS d30, ROUND(AVG(l60)) AS d60, ROUND(AVG(l90)) AS d90, ROUND(AVG(l120)) AS d120, ROUND(AVG(l180)) AS d180, ROUND(AVG(l365)) AS d365,
  ROUND(SUM(l30)) AS r30, ROUND(SUM(l60)) AS r60, ROUND(SUM(l90)) AS r90, ROUND(SUM(l120)) AS r120, ROUND(SUM(l180)) AS r180, ROUND(SUM(l365)) AS r365,

FROM w GROUP BY 1,2 ORDER BY 1,2
```
